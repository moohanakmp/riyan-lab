# Calendar recovery and structure-only Low Profit

The primary calendar's HTTP 429 is an upstream rate limit. Previously, the app hid all upcoming events after the 30-minute freshness window. It now retains the validated current-week schedule for display with its original timestamp and a stale label. Stale data never becomes a freshly checked news-risk schedule, and prior-week schedules are not displayed.

An optional `ECONOMIC_CALENDAR_FALLBACK_URL` can point to an independent HTTPS JSON feed using the existing title/country/date/impact/forecast/previous/actual schema. Full current-week validation and USD coverage are required. There is no default second provider or fabricated schedule. Primary cooldown and source label persist across restarts (Flyway V9). Independent fallback refreshes can continue while the primary honors Retry-After. If no validated schedule exists and both feeds fail, the app reports unavailable.

Low Profit entries now use only confirmed closed 5m support/resistance or first order-block retest rejections, with volume confirmation. Order blocks require displacement and a prior structure break; invalidated and previously tested blocks cannot authorize new entries. Legacy EMA continuation, pullback, breakout and band-only entry switches no longer authorize Low Profit entries. Headline tone, calendar readiness and scheduled events cannot block or create Low Profit entries. Other signal workspaces keep their existing behavior.

The configurable dollar target sets net take-profit after modeled spread, capped before opposing structure. Minimum net reward/risk is 1.3. A $2 target can therefore reject a setup with more than approximately $1.54 stop risk. Stops remain beyond structural invalidation; position size stays 0.01 lot. Target size never forces a wider position or an inward stop. Daily goal/stop, cooldown, quote freshness, market hours, account limits and durable entry approval remain active.

New basket creation logic and its enable/replay UI are retired; the server rejects new basket positions. Existing legacy positions/history remain available and retain browser stop/exit management. They are not silently deleted, closed or rewritten. New Low Profit positions retain the shared server background scanner.

Validation before PR: all 18 frontend/engine check scripts pass, including mirrored order-block fixtures, price/volume freshness, invalidation, candle gaps, configurable targets, low-profit news independence and legacy basket management. Java 21 Maven verify passes with 33 executed unit tests and 13 database integration tests skipped locally; PostgreSQL integration runs are required in CI. The public primary feed was reachable with 97 events (23 high impact) during this work. This does not verify availability from Render's network or any account's live feed.

Paper fills and replay are hypothetical. No strategy or standalone application can guarantee profitable entries. The app still requires live market-data access, its backend/database, and valid account settings for unattended scanning.
